# v0.63.1

## Summary
Re-pinned to compiler v0.63.1: the C001 classifier flake is fixed and both iter carve-outs retire (release gate now full 952/952); xiom.time.Instant moves to the monotonic runtime clock.

## Highlights

### Compiler pin v0.63.1: full release gate, C001 carve-outs retired
kind: stdlib
The C001 fix (`4bf8cf1e`) is contained in the v0.63.1 release. Both
`smoke_iter_range.xi` and `smoke_iter_find_all_any.xi` passed a 20x
compile+run stress on the pin and were removed from
`tools/known_failures/gate-exclusions.txt`; the release corpus now runs
full (952/952) with no exclusions, and `ci`/`heavy` keep running the full
corpus.

### Instant is now monotonic
kind: stdlib
`xiom.time.Instant.now()` and `Instant.elapsed()` read the runtime
monotonic clock (`monotonic_ms() / 1000`, second resolution) instead of
the wall-clock `time(0)` path, matching the type's documented contract.
`SystemTime.now()` remains the epoch wall clock. Locked by
`tools/probes/p_pin0631_shapes.xi`.

### Compiler fixes this pin relies on
kind: compiler
v0.63.1 stops false contract-evaluator aborts for clauses that read tuple
components or compare payload lengths, emits valid SMT for receiver
contracts, binds bare duplicate-leaf lz4 calls to the checker's target
(the stdlib `*_checked` rename is kept as an optional no-op), and removes
polluted-install double-indexing.

## Known issues
- None from this pin; the open compiler queue is tracked in
  `tools/known_failures/README.md`.
