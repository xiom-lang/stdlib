# v0.65.4

## Summary
Two socket-layer regressions are fixed: socket handles now use one ABI on every target (unblocking arm64 consumers), and a POSIX client disconnect no longer kills the server with SIGPIPE. No API changes.

## Highlights

### One socket-handle ABI on every target
kind: fix
xiom_socket_create, xiom_socket_accept and xiom_socket_close return int64_t on every target, widening the POSIX int fd and the Win64 SOCKET. The stdlib declarations stay `-> Int`. On arm64 the previous i32 definitions failed LLVM IR verification (`@xiom_socket_close defined with type 'i32 (i64)*' but expected 'i64 (i64)*'`), so every consumer of xiom.net.socket could not build. Probe p_socket_ffi_width (REL-20261030-1628-pulse).

### POSIX SIGPIPE no longer kills the server
kind: fix
xiom_socket_send passes MSG_NOSIGNAL where available, and the runtime ignores SIGPIPE at init as a belt-and-braces guard (macOS has no MSG_NOSIGNAL). A client that connects, closes, and then receives a server write no longer terminates the process with exit 141. Windows is unchanged. Probe p_socket_sigpipe (REL-20261030-1645-xvector).

## Breaking changes
- None.

## Known issues
- The runtime fixes are carried by the v0.65.4 compiler build (which pins this tag); the stdlib gate battery here uses the v0.64.8 pin and exercises the package surface, while the arm64/SIGPIPE integration is verified by the v0.65.4 compiler CI and PULSE's WSL/arm64 runs.
- Contract coverage remains partial in the documented no-clause tail (iter, os, math, thread, ffi, serialize, format).
- The compiler drop-family residual (REL-20261020-1704) still retains memory under repeated JSON build/parse/stringify.
- macOS and BSD event-loop support still returns an explicit error until the kqueue backend lands.
