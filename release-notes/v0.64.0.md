# v0.64.0

## Summary
Re-pinned to compiler v0.64.0 (tag c68d91de): the m193-m196 batch resolves all_types, restores TcpStream.read, makes float bitcasts exact, and allows direct runtime externs; the stdlib consumes each fix with a lock.

## Highlights

### Compiler pin v0.64.0: all_types resolved, read restored, exact bits
kind: stdlib
- m195 fixes angle-bracket generic receivers' type args: `reflect.all_types()`
  no longer heap-corrupts; it carries `ensures: result.len() == type_count()`
  and the regression lock exits 0.
- m196 gates the raw-pointer read builtin: `TcpStream.read` works again,
  locked end-to-end by the new `tests/smoke/smoke_net_tcp_stream.xi`
  loopback (the stdlib previously had no TcpStream read/write smoke, which
  is why the hijack shipped unnoticed).
- m194 makes `num.float.float_bits`/`bits_to_float` exact LLVM bitcasts;
  the fallback docs are gone and roundtrip clauses added.
- m193 allows direct externs of runtime symbols: the guard-alloc smoke now
  declares `xiom_guard_alloc` itself, retiring the probe-shim workaround.

### Closed blocker family
kind: stdlib
The compiler lane reports iter collect/contains, scrypt, shuffle/choice and
BUG-18 closed on this tree; all four are regression-locked in
`tools/probes/p_regress_*.xi` and green. `multipart_parse`'s field-read
root cause is isolated in the compiler (match-binding element type
erasure), targeted for v0.64.1. `geom.Box` confirmation: stays on the
stdlib section C rename; no compiler fix needed.

## Known issues
- `multipart_parse` Part field reads stay corrupt until the v0.64.1 fix
  (filed, compiler-owned).
