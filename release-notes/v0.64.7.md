# v0.64.7

## Summary
Typed confined faults plus the readiness follow-through: fault acknowledgment, RNG snapshots, HTTP/2 framing, socket activation and native Linux and Windows readiness.

## Highlights

### Typed confined faults
kind: fix
Confined hardware faults are now recorded and surfaced as typed HardwareFault values through xiom.error.faulted and take_fault, with signal, PC, retry and address detail. Transient guard-page faults retry once; an unacknowledged manifested fault exits 70.

### Readiness follow-through
kind: stdlib
The rand state snapshot API, the HTTP/2 frame and HPACK primitive foundation, systemd LISTEN_FDS adoption, native epoll and WSAPoll readiness, and full contract coverage on the sort surface land together. macOS readiness remains an explicit Err until the kqueue wave.

## Breaking changes
- None.

## Known issues
- The macOS and BSD event loop is not implemented yet; those platforms return an explicit Err until the kqueue backend lands.
- HTTP/2 is a primitive foundation: Huffman coding, dynamic-table inserts, CONTINUATION reassembly and connection state are future slices.
- The typed confined-fault path requires compiler v0.64.7 or newer; the previous compiler links but does not emit the fault hooks, so the two guard smokes fail there by design.
