# v0.62.4

## Summary
Re-pinned to compiler v0.62.4: the inline unsigned-compare miscompile and the Range.collect codegen failure are fixed, and both are locked by promoted regression probes.

## Highlights

### Compiler pin v0.62.4: uint32 compare + Range.collect fixed
kind: stdlib
The library moves to compiler v0.62.4, clearing the inline module-qualified
UInt32 compare misread (m186) and the parent-module `iter.range(...).collect()`
codegen failure. Both are locked by promoted probes
(`tools/probes/p_regress_uint32_compare.xi`,
`tools/probes/p_regress_iter_collect.xi`); the retired known-failure entries
are gone from `tools/known_failures/README.md`. t2 (KAT corpus) is 15/15 and
the full local battery is green on the SHA256-verified official archive.

### Deterministic release gates via the documented carve-out
kind: tooling
`release.yml` now runs the corpus with
`tools/known_failures/gate-exclusions.txt` (`run_smokes.ps1 -ExcludeFile`;
exclusions printed and counted in the JSON summary), so the release gate is
deterministic while `ci`/`heavy` keep running the full corpus.

## Known issues

- **C001 classifier flake** -- `smoke_iter_range.xi` and
  `smoke_iter_find_all_any.xi` compile-fail on roughly half of identical
  runs on both v0.62.3 and v0.62.4 (`receiver does not expose a concrete
  Vec/Slice/Array element type`). Filed as
  `tools/known_failures/p_iter_range_contains_c001.xi`; excluded from the
  release gate.
- **lz4 empty-block miscompile** -- `smoke_compress_lz4_snappy.xi` fails
  deterministically (run=5) on both pins; see
  `tools/known_failures/README.md`; excluded from the release gate.
