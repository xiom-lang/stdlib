# v0.64.4

## Summary
Contracts coverage continues across the standard library, and the JSON and string byte paths become linear, removing the large-payload slowdown that blocked data tools.

## Highlights

### JSON and string byte paths go linear
kind: fix
Parsing large JSON documents is now linear: the parser reads the raw UTF-8 bytes once instead of rescanning the string per character, and the string slice and byte-copy helpers do the same. Large numeric payloads parse in well under a second, and the Unicode-escape defect that dropped the byte after an escape is fixed.

### Contracts and coverage across the standard library
kind: stdlib
Coverage waves since the last release added clauses across math, collections, crypto, os, hash, sync and more, lifting public-function coverage from the low sixties to nearly seventy percent. The sync, crypto and hash surfaces are now almost fully covered, and every wave is locked by dedicated probes.

## Breaking changes
- None.

## Known issues
- Still open: cross-module alias type paths and method-style foreign calls; use bare type names with qualified calls.
- Still open: pre-state clauses on mut-parameter fields alias the mutated value; clause-position float vector indexing reads garbage.
- Still open: generic by-reference Option, Result and Slice parameters were fixed in the current compiler release and their clauses land next.
- Still open: tuples and nested vectors can lose element or nesting types without annotations; geom Box naming and matrix tuple inference.
- Still open: the polyhedra convex hull functions collapse on nonempty inputs; the polygon difference helper misses half-plane cases.
- Still open: cross-type generic callbacks and Result or Option payload reads in catalog clauses.
- Still open: a shape-mismatched vector reference compiles silently; the Path.exists plus println sequence can trap.
