# v0.65.0

## Summary
Reusable receive buffers and a guarded Vec copy-out path land alongside the JSON number-rendering crash fix, with no public API breaks.

## Highlights

### Reusable receive buffers
kind: stdlib
socket_recv_into and socket_recv_timeout_into fill a caller-owned Vec and reuse its capacity, so a per-connection read buffer stops allocating on every request. They return the byte count, use 0 for a clean EOF, and return Err with an empty buffer on a timeout or socket error.

### Guarded copy-out and JSON crash fix
kind: fix
The runtime gains xiom_guard_copy_out_if_arena, which returns main-heap Vec buffers in place instead of copying them on every confined-block exit. JSON number rendering now pushes digits with an allocation-free byte loop, removing the HTTP and scatter-gather probe crash.

## Breaking changes
- None.

## Known issues
- Contract coverage remains partial in the lazy iterator adapters, the legacy numeric module and parts of math and string.
- JSON build- and parse-side retention remains compiler drop-elaboration work.
- macOS and BSD event-loop support still returns an explicit error until the kqueue backend lands.
