# v0.64.8

## Summary
Contract coverage and release-readiness cut: regex and search reach full or near-full clause coverage, core, stats, time, async and numeric precision surfaces expand, and the release is pinned to compiler v0.64.8.

## Highlights

### Contract coverage across core surfaces
kind: stdlib
Time, async, numeric precision, core, stats, regex and search now carry contracts on most public functions. Search is fully covered, regex is near full, and the readiness floor ratchet moves to the new coverage baseline. No runtime behavior changes.

### Release readiness and compiler pin
kind: stdlib
The release stays on the thread spawn/join result-buffer fix and the merged contract waves. Compiler pin v0.64.8, release notes, changelog and deterministic packaging are aligned for the next combined cut.

## Breaking changes
- None.

## Known issues
- Contract coverage remains partial in the lazy iterator adapters, the legacy numeric module and parts of math and string; the remaining gap is tracked by the readiness gate.
- A generic-struct read/write compiler defect remains open and affects the closed-channel scan path.
- macOS and BSD event-loop support still returns an explicit error until the kqueue backend lands.
