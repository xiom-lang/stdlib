# v0.65.3

## Summary
The channel handle becomes non-owning, the HTTP/2 layer gains connection multiplexing and frame transport, the server half of Server-Sent Events lands, and request parsing drops the whole-head copies. One deliberate break: the channel handle's public `.items` field is removed.

## Highlights

### Non-owning channel storage
kind: fix
sync.channel now stores its queue as raw element storage (data pointer, len, alloc_cap, cap, closed) instead of a Vec[T]. The handle form copies the cell through ptr.read / ptr.write, and a Vec field made the cell and the local copy two owners of the same items buffer (heap corruption on open/send/free, REL-20261028-1533-stdlib / REL-20261028-1617-stdlib). Elements are moved element-wise on growth and freed by channel_handle_free; the public function API is unchanged.

### Server-side SSE
kind: stdlib
sse_encode_event, sse_encode_comment and sse_encode_heartbeat build LF wire bytes (CR/LF injection rejected; multi-line data becomes repeated data: fields), and sse_write_event, sse_write_comment and sse_heartbeat write them over a TcpStream with write_all. Probe p_wave298_sse_wire covers round-trip, injection and a loopback write.

### HTTP/2 connection multiplexing and frame I/O
kind: stdlib
H2Connection adds a concurrency cap, local stream ids, received-GOAWAY drain (streams above the peer's last id are dropped; an increased last id is rejected) and local graceful drain. xiom/net/h2_io.xi adds a buffered H2Reader over a TcpStream (9-byte header plus payload reassembly, EOF/max_payload errors), h2_join_header_block (HEADERS + CONTINUATION with a block cap), h2_write_frame, h2_write_settings_ack, h2_write_ping_ack and h2_write_header_block (fragmented HEADERS/CONTINUATION). This completes the h2 primitive layer; frame I/O stays with the caller. Probes p_wave298_h2_conn_mux and p_wave299_h2_io.

### Request parsing without the whole-head copies
kind: fix
net.server.server_parse_request parses directly from the request byte buffer using (start, len) spans instead of copying the whole head into a Vec[UInt8] and a Str, then slicing request-line strings and two strings per header. Header names are lowercased in the same copy and the header vector is pre-sized. 50k-parse measurement on the official v0.64.8/v0.65.2 compilers (Windows x64): about 8,954 B/iteration before, about 857 B/iteration after; API and error semantics are unchanged. Probe p_http_parse_alloc (REL-20261027-1955-pulse-2).

## Breaking changes
- The channel handle's public `.items` field is gone. Use channel_len / channel_capacity; the public function API is unchanged.

## Known issues
- Contract coverage remains partial in the lazy iterator adapters, the legacy numeric module and parts of math and string (the documented no-clause tail).
- The compiler drop-family residual (REL-20261020-1704) still retains memory under repeated JSON build/parse/stringify; the stdlib allocation paths are not the retained shape.
- macOS and BSD event-loop support still returns an explicit error until the kqueue backend lands.
- Verified against the compiler pin v0.64.8. The v0.65.3 compiler archive is being verified by the compiler lane; this release is the stdlib half of that pair.
