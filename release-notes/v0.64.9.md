# v0.64.9

## Summary
Contract coverage and readiness reach new floors across the stdlib, and the JSON and directory IO paths release their retained buffers under repeated use.

## Highlights

### Contract coverage and readiness
kind: stdlib
The contract campaign lifts public-function coverage to 95.2 percent with 97.3 percent of functions carrying clauses, and moves the readiness floor ratchet to the new baseline. Numeric, string, compression, bits, io, core, collect and test surfaces are at or near full coverage.

### JSON and IO retention fixes
kind: fix
JSON stringification, pretty printing and minification render through byte builders with allocation-free number digits, so repeated JSON loops stay flat under a 256 MB cap. Page readers gain read_at_into with a caller buffer, and list_dir returns runtime-owned entry names so names stay valid after later allocations.

## Breaking changes
- None.

## Known issues
- Contract coverage remains partial in the lazy iterator adapters, the legacy numeric module and parts of math and string, where the remaining functions are stubs or compiler-limited.
- JSON parse-side retention still needs the compiler drop-elaboration fix.
- macOS and BSD event-loop support still returns an explicit error until the kqueue backend lands.
