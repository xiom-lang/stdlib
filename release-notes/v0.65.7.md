# v0.65.7

## Summary
HTTP/1.1 and WebSocket framing reject request-smuggling and remote-DoS shapes; large allocations request transparent huge pages; Int formatting uses an owned concat. Contract coverage is 96.1% with the EX-0 tail retired.

## Highlights

### HTTP/1.1 and WebSocket framing hardening
kind: fix
Strict Content-Length and Transfer-Encoding checks, CTL/NUL rejection, RSV/opcode/control-frame checks, valid close codes/reasons and UTF-8 text, and no negative consumed frame lengths. The request-smuggling shapes and the remote WebSocket crash are closed.

### THP large allocations and owned Int formatting
kind: fix
Large `xiom_alloc` blocks hint 2 MiB transparent huge pages before zeroing on Linux x86_64. `convert.to_string` uses the owned `+` concat so the slice temporary is freed instead of retained.

### Contract tail retired
kind: stdlib
The public API has 0 EX-0 exemptions: 276 uncovered functions carry per-function EX-1..EX-5 records, coverage is 6,716/6,992 (96.1%), and the ownership map and sign-off policy are in docs.

## Breaking changes
- `xiom.collect.threadpool.ThreadPool` is renamed `CollectThreadPool` (pre-1.0 same-leaf dedup); the public function names are unchanged.

## Known issues
- Verified against compiler pin v0.65.7.
- macOS and BSD event-loop support still returns an explicit error until the kqueue backend lands.
- The v0.65.6 tag remains immutable at its recorded commit; it is not re-pointed.
