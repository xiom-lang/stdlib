# v0.63.0

## Summary
Re-pinned to compiler v0.63.0: the lz4 empty-block miscompile is fixed and its smoke rejoins the gate, while the stdlib archive carries the arena-audit guard-alloc bound check.

## Highlights

### Compiler pin v0.63.0: lz4 fixed, gate carve-out shrinks to C001 only
kind: stdlib
`smoke_compress_lz4_snappy` is green on the official v0.63.0 archive (m190)
and is removed from `tools/known_failures/gate-exclusions.txt`; only the two
C001-flaky iter smokes remain excluded, and `ci`/`heavy` keep running the
full corpus. t2 (KAT corpus) is 15/15 and the full local battery is green on
the SHA256-verified archive.

### Runtime arena-audit bound check ships in this stdlib archive
kind: runtime
`xiom_guard_alloc` rejects `size > LLONG_MAX - 16` before the
`(size + 15) & ~15` alignment math, fault-injection locked by
`tests/smoke/smoke_guard_alloc_wrap.xi` (rc 0 with the guard, rc 1 with it
disabled). Note: the compiler's own v0.63.0 release archive bundles an
earlier stdlib revision, so its bundled lib/runtime predates this check;
the `stdlib-v0.63.0` archive carries it.

## Known issues

- **C001 classifier flake** -- `smoke_iter_range.xi` and
  `smoke_iter_find_all_any.xi` compile-fail on roughly half of identical
  runs on this pin (`receiver does not expose a concrete Vec/Slice/Array
  element type`). Filed as
  `tools/known_failures/p_iter_range_contains_c001.xi`; excluded from the
  release gate, still exercised by `ci`/`heavy`.
